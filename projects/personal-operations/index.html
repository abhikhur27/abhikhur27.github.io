Event-Driven Personal Operations Platform

Python · SQLite · Email and calendar APIs

I built this to handle the repetitive work around my email, calendar, tasks, and notes.

From an email to a task

When an email or calendar update comes in, the system picks out the details and checks whether it has seen them before. It then works out what needs to happen next, such as creating a task or preparing a reply.

The work goes into a queue. An action is only marked done after the app handling it confirms the change.

What I use it for

  • Keeping track of messages and calendar changes across connected accounts.
  • Drafting replies using the conversation and details I've already provided.
  • Checking what was sent, saved, or is still waiting for another attempt.
  • Running reminders on my desktop so closing my laptop doesn't stop them.

Keeping track when something fails

SQLite stores the job history, so a restart doesn't wipe out what the system was doing. One scheduler runs the recurring jobs. Before retrying an action, the system checks whether it already went through.

Saving an incoming email and sending me an alert are separate steps. If the alert fails, the email is still saved and the alert can be tried again.

Background scripts handle repeated checks and routine actions. AI helps interpret messages and draft replies; the system still checks the result before marking the work done.
