RuleSplit

Python · C · Linux · Packet-policy analysis

A faster path should not quietly change who gets through.

Moving a busy firewall rule onto an offload path can skip an earlier exception. RuleSplit takes an ordered policy and packet capture, builds a split that fits a prefix-table budget, and checks that every offloaded region keeps the original decision.

1. allow trusted clients to the API
2. drop everyone else going to the API

move rule 2 first → trusted clients get dropped, too

Keep the exception, move the rest

The compiler subtracts earlier matches from later rules, then breaks the remaining address and port ranges into aligned prefix rows. It counts those rows against the budget. Traffic outside the selected regions still uses the full original CPU policy.

The verifier checks each row against the ordered policy using exact integer regions. If a decision differs, it returns a concrete source, destination, ports, and protocol that expose the mistake.

A reproducible packet check

The example capture contains 1,080 synthetic packets. Python reference, split-path, and compiled C decisions matched with zero mismatches. The eight-row budget selected four rows: 640 packets took the modeled offload path and 440 stayed on CPU. Those are path counts, not measured hardware speed.

A model, not a deployed DPU

The tool supports stateless IPv4 allow/drop policies and classic TCP/UDP captures. Fragmented packets, PCAP-NG, stateful rules, and unsupported traffic fail explicitly. Row selection is a greedy heuristic, not an optimal packing claim.

The C code runs on the host CPU. A real NIC or DPU needs its own backend and validation. No Cisco hardware or proprietary traffic is used.
