StallWitness

SystemVerilog · Python · Icarus Verilog

A long waveform is not a good explanation of a small bug.

StallWitness takes a saved RTL waveform and finds the clock edges where a ready/valid data channel breaks its contract. It produces a short trace you can read in a browser, plus JSON for another tool or test.

cycle       valid   ready   data
receiver busy  1       0      7
still busy    1       0      8  ← that value needed to stay put
Read an actual failure trace ↗ Code and setup ↗

What it catches

Valid means the producer has data. Ready means the receiver can take it. While the receiver is busy, the producer must hold valid and keep that data unchanged. The checker samples before the rising edge, so ordinary register updates after a transfer do not look like protocol failures.

A second check compares the accepted data sequence with a reference run. Different latency is fine. Missing, repeated, reordered, or changed values are not.

Tested against actual RTL

The included four-entry FIFO runs in Icarus Verilog. Across eight seeds, all eight correct runs passed an independent transaction scoreboard. The checker detected all 24 fault-injected runs. The defects change stalled data, pop without ready, or stop the read pointer.

What this does not prove

This is an offline diagnostic for one data channel, not a complete AXI checker or a proof that a circuit cannot deadlock. It uses simulated RTL. I have not claimed synthesis, timing closure, FPGA-board testing, or fabricated silicon.

Independent project. No Cisco hardware or proprietary traces are used.
